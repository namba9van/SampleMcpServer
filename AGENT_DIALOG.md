# Потоковый диалог агентов

Инструмент `agent_dialog` реализует диалог `A → B → A → B` через стандартный MCP.

## Поток

Клиент отправляет `tools/call` и передаёт `_meta.progressToken`.
Сервер запускает модель A, передаёт фрагменты её ответа через
`notifications/progress`, затем запускает модель B и продолжает поток.

Финальный `tools/call` возвращает полный стенографический текст диалога.

## Недоверенные данные

Ответ модели A не становится системной инструкцией для модели B.
Ответ модели B не становится системной инструкцией для модели A.
Оба ответа рассматриваются как внешний недоверенный текст.

## Настройка

```powershell
$env:AGENT_A_ENDPOINT="http://127.0.0.1:1234/v1/chat/completions"
$env:AGENT_A_MODEL="model-a"

$env:AGENT_B_ENDPOINT="http://127.0.0.1:1234/v1/chat/completions"
$env:AGENT_B_MODEL="model-b"

dotnet run
```

Можно указать разные endpoints и API-ключи для двух агентов.

## Ограничения

- начальный запрос: максимум 32000 символов;
- количество ходов: от 1 до 20;
- отмена выполняется через стандартный `CancellationToken` MCP;
- потоковые сообщения отправляются только при наличии `progressToken`.

## Совместимость

Ожидается OpenAI-совместимый `/chat/completions` endpoint с поддержкой
`stream=true` и Server-Sent Events. LM Studio подходит для такой схемы.
